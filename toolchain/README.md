This directory is the complete public Docker build context for the Rust 1.98.1 ARM64 toolchain pilot. The Dockerfile contains only public tooling and has no `COPY` or `ADD` instruction. Its context excludes the SDK, the repository checkout, Git metadata, homes, keys, private Harmony scripts, agent state and logs. It installs Python and certificate roots, then the Wasm target for the pinned Rust toolchain. It includes no Chromium or provider CLI.

The base is the official `rust:1.98.1-slim-bookworm` Linux ARM64 platform manifest `sha256:3ebe98baef5911f8461cf81ba05644374a3c5ef1f8a33db3977bd4175f5ff1fc`. The owner observed its OCI index as `sha256:ff521445a372125ed4f76e1453a1f8098f2d05332d1601d30db1c1f62757e730` and upstream Docker source commit as `4dc5209f5e720a3d6b5eb336cabb69a424a822c1`. Registry metadata establishes the source reference; the actual compiler and image are not yet qualified. Debian package resolution and rustup downloads still require an actual recorded build and inventory.

The manual `build-toolchain` workflow defaults to static context checks. Its `build` choice creates a local runner image only, with a fresh credential-free Docker client configuration. It does not log in to a registry, publish an image or upload logs, receipts or artifacts. The build timeout bounds the CLI; an actual owner must independently establish Docker and process closure before accepting a build. The workflow makes no runtime or cleanup qualification claim.

The trusted SDK producer overrides this image's `/usr/bin/env` entrypoint with a clean environment, uses separate source, registry and output mounts, and enforces its own container limits. Its source catalog remains empty. Before adding an image to that catalog, the owner must capture the actual full `rustc -vV`, executable and host/Wasm sysroot hashes, package inventory, immutable public registry reference and inspected image ID/environment, then qualify the producer's network-free compile and cleanup boundary. Registry publication needs separate explicit owner approval and must use a source-reviewed public image such as this pilot; the local compiler image containing private Harmony scripts is excluded.

This is a toolchain image, not an `opaque-compile/v1` consumer. It supplies neither an opaque Rust facade nor a compiled dependency graph, rustc shim, consumer entrypoint or SDK approval. The consumer SDK catalog stays empty until those contracts and actual ABI/consumer execution are qualified. Compiled Rust metadata, generics, constants and bitcode can disclose implementation information; an rlib does not establish source confidentiality.
